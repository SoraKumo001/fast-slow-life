# Phase 4 仕様 ― ダンジョンv2（ノードマップ＋パーティ＋襲撃イベント）

前提: Phase 3 完了（commit `079ec3d` push 済み）。本フェーズは 4a（探索の空間化）と 4b（襲撃イベント）の2段で実装し、コミットも分ける。
目的: 一本道の奥行き移動を「分岐のある地図の探索」に変え、脅威度100%を即死ではなく防衛戦にする（決定 C）。

## 1. 現行コードの実態（確認済み）

- 村人の位置は `villager.dungeonState { currentDepth, targetDepth, lane, phase, targetNodeId }`。targetNodeId は既に itemId / monsterId を指す「ノード」概念がある
- 移動は gatherLogic / huntLogic 内の目標深度へのイージング。戦闘は combatEngine、狩りは `processPartyHunt` が**同一ターゲット村人のパーティ戦闘を既に実装**している
- 探索度（explorationProgress）は active 村人の能力値で進み、30/70/100% で素材・魔物が解放、100% でボス挑戦可能になる
- 脅威度は `threatLogic.updateAllThreatLevels` が 100% 到達で gameOver を返す。お布施で下げられる
- 採取物は村人の `pool` に入る。買取（poolPurchase）は村人が町にいる時だけ行われる前提で容量を設計する（実装時に呼び出し条件を確認し、違えば町にいる村人だけに買取を限定することも本フェーズの変更に含める）

## 2. Phase 4a ― ノードマップと探索の見える化

### 2.1 ノードグラフ（新規: `src/store/dungeonMap.ts`、純関数）

- ダンジョンごとに決定論的にグラフを構築する。ノード = 入口（depth 0）＋ 各採取ポイント（itemId）＋ 各魔物（monsterId）＋ 最深部のボス門（depth = maxDepth）
- ノードの表示座標: x = lane を広げた値（lane × 6）、z = depth。同一 depth 帯のノードは横に並ぶ
- エッジ: depth を昇順に見て、隣接する depth 帯のノード同士を結ぶ。各ノードは前の帯の最も lane が近いノード2つまでと接続（入口は最初の帯全てと接続）。決定的であること（同じ入力で同じグラフ）
- 関数: `buildDungeonMap(dungeon): { nodes, edges }`、`nodeById`、`pathBetween(map, fromId, toId)`（BFS。表示用）、`nearestNodeAtDepth(map, depth)`
- テスト: 全ノードが入口から到達可能、決定的、帯の順序が depth 昇順と一致

### 2.2 霧（fog of war）

- 新規保存フィールド: `revealedNodes: Record<dungeonId, string[]>`（ノードIDの配列）
- 解放条件: いずれかの村人の currentDepth がノード depth の ±15m 以内に入ったら、そのノードとグラフ上で隣接するノードを解放する（処理は exploration フェーズに相乗り）
- 未解放ノードは、ミニマップと全景ビューで「？」表示にし、素材名・魔物名を出さない。ただし**村人のAI・命令の対象選択は従来どおり**（霧は表示層の概念。プレイヤーの命令UIでも未解放ターゲットは「未知の採取ポイント」のように伏せてよいが、選択自体は可能にすること）
- 移行（§5）: 既存セーブは explorationProgress に応じて、解放済み進捗以下の depth のノードを解放済みにする

### 2.3 表示（DungeonThreeViewport / DungeonDepthMinimap / DungeonPanel）

- DungeonThreeViewport: 一本道の床を、ノード位置の円形プラットフォーム＋エッジを結ぶ道に置き換える。村人・魔物の配置は既存の depth/lane 座標系を活かしつつ、ノード付近ではノード座標にスナップして見せる。未解放ノードのプラットフォームは暗くし、ラベルを出さない。視覚イベント（攻撃・採取エフェクト等）の仕組みは維持
- DungeonDepthMinimap: 縦の深度バーから、ノードグラフの SVG ミニマップ（x=lane, y=depth、エッジ線、解放済みノードは種類アイコン、未解放は ？、村人はドット）に置き換える
- DungeonPanel: ダンジョンごとにミニマップ＋解放率（解放ノード数/全ノード数）を表示する。既存の探索度表示は残す

### 2.4 所持容量

- 村人の所持容量 `carryCapacity(villager) = 10 + floor(STR / 2)`（個数）。現在量は pool の個数合計
- 容量に達した村人は採取を止めて帰還する（既存の returning 導線に乗せる）。狩りのドロップも pool に入るなら同様に扱う
- 表示: 村人カードと DungeonPanel の探索中村人に「所持 x/y」を出す

### 2.5 パーティの可視化と派遣

- DungeonPanel で、同一ダンジョン・同一 targetNodeId の active 村人をパーティとしてまとめて表示する（リーダー＝先頭の村人名＋人数、合算所持量）
- DungeonAssignModal で最大4人まで複数選択して同じターゲット（採取/狩り）を割り当てられるようにする。到着後の戦闘は既存の processPartyHunt の合流に任せる（新規のパーティ管理状態は作らない）
- 帰還指示: DungeonPanel の村人行とパーティ行に「帰還」ボタンを置く。押すと対象村人はその場で帰還を開始する（既存の traveling_back / returning の状態遷移を使う。新規アクションとして実装）

### 2.6 撤退

- 戦闘で HP が 30% を切った村人は、そのターゲットから離脱して帰還する（既に同等の挙動がある場合は重複実装せず、ある旨を報告する）

## 3. Phase 4b ― 襲撃イベント（脅威度100%の置き換え）

### 3.1 発生

- `threatLogic` の 100% 到達時の gameOver を廃止する。代わりに襲撃状態を作る:
  `raid: { dungeonId, arrivesAtElapsedHour, monsterIds: string[] } | null`（新規保存フィールド）
- 到達したダンジョンの魔物から 3〜5 体（そのダンジョンの monsters を強さ順に、決定論的に選ぶ）が町へ進軍する。到着まで 6 時間。脅威度は進軍中 100% に留まる
- 発生時に警告ログ＋バナー表示（§3.4）。進軍中はそのダンジョンへの新規派遣を止める（派遣UIとスケジューラの両方）

### 3.2 防衛戦

- 到着した時間ティックから、防衛戦を1時間ごとに解決する。防衛側 = 町にいる村人全員（派遣中・移動中以外。休息中も HP が残っていれば参加）
- 戦闘計算は combatEngine の既存式を使う（パーティ対モンスター群のラウンド解決を、防衛側全員 vs 襲撃群で回す）。村人は HP 0 で「戦闘不能」になり休息に回る（死亡はしない、既存の慣例どおり）
- 襲撃側が全滅 → 勝利: 脅威度を 30% にリセット、ドロップ（そのダンジョンの採取物から数点）を在庫へ、勝利ログ
- 防衛側が全員戦闘不能 → 敗北: 金庫の 20% と在庫の一部を略奪され、建設済み施設1つが Lv-1（Lv1 未満にはならない）。脅威度を 50% にリセット。**ゲームオーバーにはしない**
- 防衛戦の間、町の村人は通常の生活・作業を止めて防衛に回る（townSpatial の行き先解決で門に集まるよう、Phase 1 のボス戦分岐と同種の扱いにする）

### 3.3 脅威度の残り

- お布施・ボス撃破による脅威度低下は従来どおり。襲撃後は §3.2 のリセット値から再上昇する
- 破産など他のゲームオーバー条件は従来どおり維持する

### 3.4 表示

- 襲撃バナー: 進軍中は「◯◯の群れが接近中（到着まで X 時間）」、防衛戦中は「防衛戦中」をヘッダー下に表示する（ActiveBossBar と同格の新規コンポーネント RaidBanner）
- 町ビュー: 防衛戦中、門の外に魔物のポリゴンを並べ、防衛側村人が門前に集まる様子を見せる（GameTownViewport への最小限の追加。難しければバナーとログのみでも可とし、その旨を報告する）

## 4. 戦闘・採取の数式は変えない

combatEngine の与ダメ・被ダメ式、gatherLogic の採取量、huntLogic の出現・ドロップ率は変更しない。変えるのは「空間の表現」「容量」「帰還・撤退の判断」「脅威度の到達点」だけである。

## 5. セーブ移行

- SAVE_VERSION 8 → 9。v8→v9 マイグレーション: `revealedNodes` を explorationProgress から初期化（進捗% × maxDepth 以下の depth のノード＋入口を解放済み）、`raid = null`
- initialState に同初期値を追加

## 6. ゲート

1. `pnpm build` 成功
2. `pnpm test:run` 全緑（件数を減らさない）。新規テスト: dungeonMap（到達可能性・決定性）、容量（上限で帰還すること）、襲撃（発生→勝利/敗北の両分岐、ゲームオーバーにならないこと）
3. `pnpm test:balance` を変更前後で比較（Phase 3 と同じ一時設定の方法でよい）。探索収入の激減や破産率の大幅悪化があれば数値を報告して止まる
4. 変更範囲: 探索・ダンジョン表示・脅威度・襲撃まわり＋型＋永続化。経済（Phase 3 のファイル）と生活AI（Phase 2 のファイル）には触らない（townSpatial の防衛時分岐追加のみ例外として許可）
