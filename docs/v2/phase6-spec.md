# Phase 6 仕様 ― 失敗が成立する戦闘へ（ボスHPの持続ルール変更とバランス確定）

前提: Phase 5 完了（commit `9dca38b` push 済み）。Phase 5 のバランス調整は定数・データのみで、目標帯のうち「通常戦略クリア率 30〜60%」だけが未達（実測 100%）に終わった。本フェーズはユーザーの判断により、システム側のルール変更まで踏み込んでこの1点を回収する。

## 1. 現行コードの実態（確認済み）

- ボス戦は `bossActions.startBossBattle` で始まり、ボスの残りHPは `ActiveBossState.currentHp` としてゲーム状態に**永続化**される。挑戦が失敗・中断してもHPは減ったまま残り、再挑戦は削り切り競争になる（消耗戦で必ず勝てる）
- 交戦中の回復はあるが `BOSS_REGEN_PERCENT = 0.002`（最大HPの0.2%/時、交戦中のみ）で、パーティの火力に対して無視できる水準
- シミュレーション（`balanceSimulator.worker.ts`）の上限は 900 日（MAX_HOURS = 900×24、シミュレーション側のパラメータでゲーム本体のルールではない）。ゲーム本体の終了条件は 全tier制覇（クリア）/ 破産 / 全員戦闘不能
- Phase 5 の分析: 通常戦略のランは1周目で tier 2〜3 に停滞するが、転生（ソウル強化）を挟んだ2周目以降は上記の消耗戦構造により必ず全tierを制覇する。破産は全ての支出が予算制のため構造的に起きない。よって失敗が実質存在しない

## 2. 本体変更 ― ボス戦の離脱リセット

### 2.1 ルール

ボス戦が勝利なく終わったら、ボスは全回復して次回挑戦は満タンから始まる。離脱の成立条件は次の2つ:

- **(a) 全滅**: そのボス戦の全アタッカーが戦闘不能（HP 0）になった時点で即時離脱
- **(b) 放棄**: 交戦可能なアタッカーが1人もいない状態が **24時間** 続いたら離脱（帰還・撤退・編成変更で全員が離れたケース。治療のために一時下がる再挑戦を即リセットしないための猶予）

離脱時:
- `activeBoss` を破棄する（次回の `startBossBattle` は満タンHPで生成される。既存の生成経路をそのまま使う）
- ログを出す: 例「◯◯は巣へ戻り、傷を癒した。次に挑むときは万全の状態だ」
- 脅威度・探索度など他の状態は変えない

### 2.2 実装上の注意

- 「交戦可能なアタッカー」の定義は `bossBattle.ts` の attackers 抽出（attackerIds に含まれ status が active）と揃える。ただし移動中（traveling_to でボスへ向かっている）など、交戦へ復帰する途中の状態があれば、それも「離脱していない」に数えること。実装時に bossActions / bossBattle / villagerScheduler の状態遷移を確認して決める
- (b) の経過計測には `ActiveBossState` へ任意フィールド `lastEngagedAtElapsedHour` を追加してよい（累計時間 = (day-1)×24 + hour）。旧セーブに無ければ「現在時刻」として扱うフォールバックを入れ、SAVE_VERSION は上げない
- 戦闘中のアタッカー追加参戦は従来どおり可能で、その場合は離脱タイマーをリセットする
- 与ダメージ・被ダメージの計算式は変更しない。変えるのはボスHPの持続ルールだけ

### 2.3 UI

- ボス挑戦の導線（挑戦モーダル等、既存の開始UI）に注意書きを1行追加する: 「全滅・撤退するとボスは全回復します」
- ActiveBossBar は activeBoss が消えれば自然に消える（既存挙動）。追加のUIは作らない

### 2.4 テスト（新規）

- 全滅で activeBoss が破棄され、再挑戦が満タンHPから始まる
- 24時間の不在で離脱する / 24時間未満では離脱しない
- 交戦が継続している間はリセットされない
- 追加参戦で離脱タイマーがリセットされる

## 4. 追加レバー（§2 で届かない場合のみ、この順に1つずつ）

1. **転生の逓減**: ソウルアップグレードの効果に周回ごとの逓減、またはコスト逓増を入れる（データ＋小さな式変更可）。狙いは「2周目で必ず届く」の解消
2. **経験値カーブ**: 高レベル帯の必要XP引き上げ（データ）。ボス挑戦のレベル条件に届く速度を落とす
3. **襲撃敗北のエスカレーション**: 同一ラン内の防衛戦敗北が続くと略奪率が上がる（20% → 敗北ごとに +10%、上限 50%）。破産という失敗経路を到達可能にする

- 追加イテレーションは最大3回。各回シミュレーションを取り、記録する
- 3回で届かなければ最も近い構成で止め、未達の指標と理由を報告する（帯は広げない）
