# Phase 7 仕様 ― ダンジョン2D迷路化（二次元座標と経路移動）

前提: Phase 6 完了後に着手する（ボス戦・バランスに触るため、ツリー競合を避ける）。
目的: Phase 4a のノードグラフは「depth 帯を lane で広げた層状グラフ」で、実質は幅のある一本道だった。ダンジョンに二次元座標を持たせ、迷路状の構造を実際に進む形に変える。

## 1. 現行コードの実態（確認済み）

- `src/store/dungeonMap.ts`: ノード = 入口＋採取（itemId）＋魔物（monsterId）＋ボス門。表示座標は x = lane × 6、z = depth。エッジは隣接 depth 帯同士のみ
- シミュレーション側の位置は `dungeonState.currentDepth`（入口からの距離 m）の一次元で、採取・狩り・霧・探索度はすべて depth をキーに動く。depth の供給元は `dungeonSpatialHelper` の `getGatherDepth` / `getMonsterDepth`（マスタデータの depth を返す）
- 霧は「村人の currentDepth ±15m のノード＋グラフ隣接」を解放する（`computeRevealedNodes`）
- 3D ビューはノードのプラットフォーム＋エッジの道で描かれ、村人は target ノード付近でスナップ表示される

## 2. 設計方針 ― depth の意味だけを「迷路の経路距離」に差し替える

シミュレーションの一次元性（currentDepth のイージング、探索度、霧の半径、ボス門 = maxDepth）は維持する。変えるのは座標の出自:

- 各ノードにグリッド座標 (gx, gy) を持たせ、表示座標を x = gx × 6、z = gy × 6 とする（z = depth を廃止）
- ノードの `depth` は「入口から迷路を辿った経路距離（m）」に再定義する。`getGatherDepth` / `getMonsterDepth` はマスタデータの depth ではなく、所属ノードの経路距離を返すよう差し替える（消費側は無変更で追随する想定。実装時に全消費箇所を確認すること）
- ボス門の経路距離がちょうど maxDepth になるよう、1セルの歩幅（m）を ダンジョンごとに maxDepth / ボスまでの歩数 で決める。他ノードの経路距離は比例して定まる

## 3. 迷路生成（`dungeonMap.ts` の拡張、純関数・決定的）

- グリッド: 横 7 列。縦は maxDepth に応じて rows = clamp(round(maxDepth / 8) + 1, 8, 40)（森100→14、鉱山150→20、谷200→26、最深300→38 程度）
- 生成: ダンジョンIDのハッシュを種にした PRNG（mulberry32 等）で再帰的バックトラッカにより全セルを結ぶ spanning tree を作り、壁を約10%追加で取り払ってループを作る（完全迷路にしない。経路選択が生まれる）
- 入口セル: 最下段の中央。ボス門セル: 入口からの経路歩数が最大のセル
- コンテンツ配置: 採取・魔物をマスタデータの depth 昇順に並べ、経路距離順にソートしたセルへ等間隔に割り当てる。決定的なタイブレーク（セル座標順）を使う。目安として、行き止まりセルは採取、3つ以上の接続を持つセルは魔物を優先する（割り当て可能な範囲で）
- グラフのノードは全セルとする: 種別は entrance / passage（素通りのセル）/ gather / monster / boss_gate。エッジは掘られた隣接のみ
- 既存API（`pathBetween` BFS、`nearestNodeAtDepth`、`computeRevealedNodes`、`initialRevealedNodes`）は新しいグラフでもそのまま意味を持つこと。`nearestNodeAtDepth` は経路距離ベースで従来どおり

## 4. 霧とセーブ

- 霧の解放規則は現行を維持する（村人の currentDepth ±15m のノード＋隣接を解放）。セルが増える分、隣接解放の意味が「周囲の通路が見える」になる
- 解放率の表示（DungeonPanel の「解放 x/y」）はコンテンツノード（採取・魔物・ボス門）だけを数える（passage は数えない）
- 既存セーブの `revealedNodes` はコンテンツノードのID（itemId / monsterId / entrance / boss_gate）がそのまま有効。読み込み時に、新マップに存在しないIDを落とし、探索度からの初期解放（`initialRevealedNodes`）と union する。SAVE_VERSION は上げない

## 5. 表示

### 5.1 3Dビュー（DungeonThreeViewport / environmentBuilder）

- プラットフォームはコンテンツノードにのみ置き、掘られたエッジには通路の帯を引く（現行の仕組みの拡張）
- **壁**: グリッド内で掘られていない隣接辺に低い壁（生け垣・岩壁など、ダンジョンのテーマに合う素材）を置き、迷路として読めるようにする。未解放セルの壁・通路は暗くする（端点のどちらかが解放済みなら通路は見せる、程度の近似でよい）
- 村人・魔物の表示位置: currentDepth（経路距離）に対応する経路上の点を、入口からターゲットノードへの BFS パスに沿って補間する。Phase 4a の「ターゲット付近スナップ」はこの一般化に置き換わる
- 装飾（木・岩）はセル外・壁際に散らす（現行の散布を流用）。ジオメトリとマテリアルは共有し、セル数（最大 7×40 = 280）でも重くならないこと

### 5.2 ミニマップ（DungeonDepthMinimap）

- SVG のグリッドマップに置き換える: セルを正方形で描き、解放済みは種別の色・記号、未解放は暗色。通路はセルの接続として読める形にする（セル同士の間隔を詰め、掘られた辺だけ開ける描き方でよい）
- 村人はドットで現在位置（経路補間後の二次元座標）に置く。クリックで深度移動する既存の操作がある場合は、経路距離への変換として維持する

### 5.3 DungeonPanel

- 解放率は §4 のコンテンツ基準。パーティ表示・帰還ボタンなど Phase 4a の機能はそのまま

## 6. バランスへの影響

- 経路距離は直線距離より長くなるが、§2 の歩幅校正によりボス門 = maxDepth に一致し、コンテンツの経路距離もデータ depth と同程度の分布になる想定。移動時間の総量は大きくは変わらないはずだが、実測で確認する
- 実装後にバランスシミュレーション（30回 × 2戦略）を回し、Phase 6 の最終結果と並べる。目標帯（Phase 5 §3.1）から外れた場合は、まず歩幅校正の範囲（ボス経路距離の一致方法）を見直し、それでも外れる場合は数値を報告して止まる（Phase 5/6 のレバーを勝手に戻さない）

3. バランス: §6 のとおり
4. スクリーンショット: ダンジョン全景モーダルで迷路（壁・分岐・霧）が読める画面、ミニマップのグリッド表示
