# Fast Slow Life 一新計画 v2 ―「眺めるポリゴン・スローライフ」

作成: 2026-11-16 / 対象: `SoraKumo001/fast-slow-life` (master `d24a99c`, 2026-11-14 push)
現行規模: TypeScript 約19,140行 / 192ファイル / テスト41ファイル、React 19 + Zustand 5 + Three.js 0.187 + Vite 8 + Tailwind 4

---

## 0. 結論を先に

現行版は「テキスト4カラムで管理する」ゲームで、3Dはダンジョン通路だけにある。一新の軸は1本に絞る。

> **プレイヤーの仕事を「数値を管理すること」から「生活を眺めて、町に介入すること」に変える。**

- 町と村人を主画面のポリゴン空間にし、村人が家→職場→店→食堂→家と実際に歩いて生活するのが見える
- 経済は「プレイヤーが売値×2で全部買い取る中央集権」から「村人・店・町金庫の間でゴールドが循環する」仕組みに作り直す
- ダンジョンは「奥行き100〜300mの1本通路」から「マス／ノードで分岐するポリゴン立体マップで、行って帰る判断がある探索」に作り直す
- 技術スタックは変えない。Three.js の既存資産（村人・モンスター・採取ノード・環境の4ビルダー、638行の `DungeonThreeViewport`）を町シーンへ横展開するのが最短路

セーブデータは互換を捨てる（`saveVersion` を上げて新規開始に寄せる）。中途半端な互換維持が一番コストが高い。

## 2. 新コンセプトとデザインの柱

**タイトル据え置き / 副題案: Fast Slow Life ― ポリゴンの町**

柱は3つだけに絞る。柱に入らない要素は今回入れない。

1. **生活が見える** ― 村人の1日が空間で読める。誰がどこで働き、何を食べ、誰と話し、いつ寝るかが見えることが報酬になる
2. **経済が回るのが見える** ― モノとゴールドの流れが町の中で完結し、滞ると店が空になり、村人が困るのが見える
3. **探索は行って帰る冒険** ― ダンジョンは「派遣して待つ場所」ではなく、パーティがポリゴンマップを進み、欲張るか帰るかを決める場所にする

逆に捨てるもの: 完全な市場経済シミュレーション（READMEの「実装外」にあるもの）、装備強化+値、村人の恋愛・結婚・老化のフル実装（欲求と会話までで止める。次期拡張に回す）。

## 3. 柱1 ― ポリゴンの町と「生活が見える」村人

### 3.1 町の空間設計

- **グリッド町**: 32×32マス（1マス=2m想定）のアイソメ／斜め見下ろしが基本。カメラは「固定気味の見下ろし＋ズーム＋回転（90度刻み）」を推奨。自由カメラは操作コストが高いので付けない（要判断事項A）
- **建物 = 施設**: 既存11施設をそのまま建物にする。各建物はポリゴンでレベルが形に現れる（Lv1小屋→Lv3屋根・煙突・看板・拡張）。アップグレードは数値ではなく町の見た目が変わることが主報酬になる
- **新規に足す建物**: 村人の家（世帯ごとに1軒、初期5軒）、広場（井戸・掲示板・市が立つ場所）、倉庫、町の門（ダンジョン／交易への出発点）
- **小物と自然**: 木・畑の畝・柵・街灯・井戸・屋台は `InstancedMesh` で量産。既存 `environmentBuilder` の側面プロップ生成（seed付き配置）を町でも使う
- **昼夜と天気**: 1日を色温度で表現（朝焼け→昼→夕→夜は窓明かりと街灯）。天気は晴／雨／雪の3種で、雨の日は畑の成長↑・採取↓など軽い効果だけ付ける
- **描画予算**: 村人最大14→20人、建物約20、プロップ数百でも `flatShading` + テクスチャなし + Instancing でモバイルでも60fpsを狙う。影は1方向のベイク気味シャドウのみ

### 3.2 村人のポリゴン化（既存ビルダーの拡張）

既存 `villagerMeshBuilder`（Box胴体＋職業別帽子・武器、歩行/採取/戦闘アニメ）は土台として十分。足すもの:

- **個体差**: 身長0.9〜1.1倍、肌・髪・服の色バリエーション、名前プレート（頭上、ホバー／選択時のみ）、感情アイコン（吹き出し: 🍞空腹、💤眠い、💬会話、⚠不満）
- **アニメ追加**: 座る・食べる、寝る（家で横＋Zzz）、運ぶ（箱を持つ）、店で買う（手渡し）、会話（向かい合って頷く）、倒れる。いずれも既存の腕・脚ピボット回転の延長で作れる
- **モンスターも同規格に**: 既存 `monsterMeshBuilder` をダンジョンv2のマス配置に合わせて流用

### 3.3 生活シミュレーション（今回の心臓部）

現行の `status: idle/traveling/active/resting` + `order: gather/hunt/rest` を、**スケジュール＋欲求（Utility AI）**に置換する。

**1日のスケジュール（職業ごとにテンプレート）**

| 時刻 | 農民 | 鉱夫・木こり | 職人 | 戦士・猟師 | 共通 |
|---|---|---|---|---|---|
| 06–07 | 起床・朝食（家 or 食堂） | 同左 | 同左 | 同左 | 朝食で食料を消費 |
| 07–12 | 畑仕事 | 採取場／ダンジョンへ出発 | 工房でクラフト | ダンジョン探索 | |
| 12–13 | 広場・食堂で昼食＋会話 | 同左 | 同左 | 帰還次第 | 社会欲求が回復 |
| 13–18 | 畑仕事 | 採取・探索継続 | クラフト | 探索継続 | |
| 18–20 | 店で買い物・夕食 | 同左 | 同左 | 同左 | その日の稼ぎを使う時間 |
| 20–22 | 自由（広場・宿屋で団らん） | | | | プレイヤーが眺めて一番楽しい時間帯 |
| 22–06 | 就寝（家） | | | | HP・スタミナ回復は「寝た時間」に比例 |

**欲求パラメータ（各0〜100、村人ごと）**: 空腹・疲労・健康（HPと統合）・満足（所持金と食事の質）・社交。毎時、欲求の低下と現在地・職業から行動スコアを計算し最高の行動を選ぶ ― 現行の採取スコア式と同じ「重み付きスコア」文化なので移行しやすい。

**プレイヤーの指示の出し方を変える**: 一人ずつ order を出す現行方式から、

- 職業と勤務先（どの施設／どのダンジョン担当か）の任命
- 町の条例（例: 食料価格の上限、残業禁止、危険なダンジョン立入禁止）
- 優先目標（現行の目標個数システムを「町の需要ボード」として広場の掲示板に可視化）

の3点に集約する。細かい行動はAIに任せ、プレイヤーは「町の方針」を決める人になる。これが "Fast（介入は速く）Slow（眺める生活）" のタイトル回収になる。

**見える化の仕掛け**: 村人クリックで「今日のあしあと」（タイムライン: 07:00 畑→12:00 食堂でパン…）を表示。ログは現行の文字列ログから、この個人タイムライン＋重要イベント通知に再編する。

## 4. 柱2 ― 経済システム v2「循環する経済」

### 4.1 現行経済の何が問題か

- 買取価格 `売値×2` 固定・自動買取のため、価格シグナルが存在しない。在庫が余っても不足しても何も起きない
- ゴールドの源泉が交易輸出と買取の差額に偏り、村人の所持金は「プレイヤーから渡されるもの」でしかない
- 食料代2G・宿代のような徴収はあるが、村人が「自分の稼ぎで暮らす」感覚がない

### 4.2 v2 の構造 ― 3つの財布と夕方の精算

```
        ┌─ 外部（交易・ダンジョンの宝）── ゴールドの唯一の源泉
        ↓
  [町金庫] ←税・施設利用料─ [店（施設）] ←購入─ [村人の財布]
        │                       ↑ 在庫・価格        │ 賃金・売却
        └─ 公共事業（建設・お布施・福祉）      [生産・採取・討伐]
```

- **村人の財布**: 収入は「勤務先からの賃金（時間給×職業・Lv）」と「採取物の店への売却」。支出は食料・家賃（家のランクで週次）・装備・回復薬・娯楽（宿屋の酒場枠）。貯蓄目標を持ち、貯まると装備や良い食事に使う ― 消費行動が見えることが生活感になる
- **店（施設）**: 各施設が在庫と価格を持つ。価格は `基準価格 × 在庫係数（在庫が少ないと上がる） × 需要係数（需要ボード連動）` で毎日朝に改定され、店頭の看板に「↑↓」で見える。プレイヤーは店ごとに「価格方針（安く薄く／標準／高く厚く）」だけ決める
- **町金庫（プレイヤー）**: 収入は店の売上税（既定10%）・家賃・交易差益。支出は建設・アップグレード・賃金補助・お布施・非常時の食料配給。現行の「プレイヤーゴールド＝全財産」から「町の財政」に意味を変える
- **夕方の精算（18時の日次処理）**: その日の売買を一括で確定し、「町の家計簿」画面で内訳（誰が何を買ったか、どの店が儲かったか）を見られるようにする。現行の毎時バラバラ徴収をここに集約し、ログのノイズも減らす
- **pool（仮置き場）とツケは廃止**: 代わりに「店の買取上限（店の現金）」と「村人の借金は満足度低下＋転職・離村リスク」に置換。能力0.7倍のツケデバフは分かりにくいので廃止
- **交易 v2**: 馬車は町の門から実際に出発し、帰着時に門で荷下ろしが見える。友好度は廃止し「契約（定期便）」に簡素化。価格トレンドは毎日ランダム1件から、「他町の需要イベント（例: アイアンポートで剣の買い付け強化・3日間）」に変え、掲示板と噂話（村人の吹き出し）で伝わるようにする
- **インフレ対策**: ゴールドの源泉を外部（交易・宝）に限定し、賃金・家賃・食費で内部循環させる。バランスシミュレータに「30日後の金庫残高・村人の平均貯蓄・食料在庫」を新ゲートとして追加する

### 4.3 段階導入（経済は一気に変えるとバランスが崩れる）

1. **v2a**: 財布を3つに分けるだけ（価格は固定のまま）。家計簿画面を追加
2. **v2b**: 店の在庫価格（在庫係数のみ）を有効化
3. **v2c**: 需要ボード・他町イベント・賃金と家賃を有効化

## 5. 柱3 ― ダンジョン探索 v2「行って、欲張って、帰る」

### 5.1 空間構造の変更

- 現行: 奥行き方向の1本通路（depth 100〜300、lane −1.5〜1.5）
- v2: **ノードグラフ型の立体マップ**。各ダンジョンは 12〜20 ノード（部屋・採取場・分岐・休憩所・ボス部屋）で構成され、ポリゴンで俯瞰表示される。探索で隣接ノードが開示される「霧」付き
- ノード種別: 入口／採取（種類別）／通常敵／強敵／宝箱／休憩所（焚き火・その場で食事と小回復）／近道（開通すると帰還が速くなる）／ボス
- 既存5ダンジョン（森・廃鉱山・魔獣の谷・世界樹・深淵）のテーマ・素材・モンスター・ボス・Tier解放はそのままノード配置に変換する。データの作り直しは配置だけ

### 5.2 探索のゲーム性

- **パーティ制**: 派遣は最大4人のパーティ単位。ポリゴン上で隊列を組んでノード間を歩く。現行の「1人ずつ別々に深度を進む」方式は廃止
- **スタミナと帰還判断**: 奥へ進むほど帰還コストが増える。「あと1ノード欲張るか、荷物とHPを守って帰るか」が毎回の判断になる。荷物（持ち帰り容量）を新設し、満杯なら採取できない
- **戦闘**: 現行の自動ターン制（命中・クリティカル・ダメージ式、僧侶ヒール、ポーション自動使用）は計算式をそのまま残し、演出だけポリゴン側（既存の attack/crit/miss 等の `DungeonVisualEvent`）に寄せる
- **リスポーン→再生と枯渇**: 採取ノードは取り尽くすと枯渇し、日単位で再生。現行の時間リスポーン（3〜16h）は日次再生に簡素化
- **探索度**: 「踏破したノード割合」に再定義。100%でボス部屋が開く現行ルールは維持
- **脅威度との接続**: 脅威が上がるとダンジョンの敵が強くなるだけでなく、**モンスターが町の外周に現れて畑や採取場を荒らす**イベントに変える。お布施は「門の守り強化・結界」に読み替え、町で効果が見えるようにする。100%即ゲームオーバーは「町への襲撃で防衛戦→敗北でゲームオーバー」に緩和するかは要判断事項C

### 5.3 町との接続

ダンジョンは町の門から出発する隣接マップとして描く（別画面に切り替えず、カメラが門の外へパンする／小マップ切替）。採取場（森の入口・川原など安全な採取専用ノード群）をダンジョン手前に置き、非戦闘職の日常の仕事場にする ― 生活（柱1）と探索（柱3）が同じ空間でつながる。


## 7. 技術計画

- **スタック据え置き**: React 19 / Zustand / Three 0.187 / Tailwind 4 / Vitest。エンジン乗り換え（Phaser・Unity等）はしない ― 既存のシミュレーションとテスト資産41ファイルを捨てる理由がない
- **シミュレーションと描画の分離を徹底**: `store/` の tick 処理は座標（マス・ノードID）までしか持たず、Three 側は補間して滑らかに歩かせる。現行ダンジョンの `dungeonState（depth/lane/phase）`＋描画補間のパターンを町にも適用する
- **新規モジュール**:
  - `src/data/townLayout.ts` ― 町のマス・建物配置・経路グラフ
  - `src/store/life/` ― スケジュール、欲求、Utility AI、経路探索（グリッドA*）
  - `src/store/economyV2/` ― 店在庫・価格改定・夕方精算・家計簿
  - `src/data/dungeonMaps.ts` + `src/store/dungeonV2/` ― ノードマップ、パーティ移動、帰還判定
  - `src/components/three/town/` ― `TownViewport`、建物ビルダー、小物ビルダー、村人の町アニメ拡張
- **性能**: 経路探索は1時間tick時にまとめて計算（フレーム毎にやらない）。描画は `requestAnimationFrame` で補間のみ。InstancedMesh と geometry 共有でドローコールを 200 以下に抑える
- **テスト／ゲート**: 既存テストは「残す領域」については維持し、作り直す領域はテストごと書き換える。各フェーズ完了条件に ①型チェック＋全テスト緑 ②バランスシミュレータで30日完走（破産・全滅しない）③実機で町が60fps近辺、を置く
- **セーブ**: `saveVersion` を上げ v2 は新規開始のみ。旧セーブの読み込みは「旧版として結果だけ表示して転生SPに換算」で受ける（任意・後回し可）

## 8. フェーズ計画（順序と完了条件）

| Phase | 内容 | 成果物 | 完了条件（ゲート） |
|---|---|---|---|
| **0. プロトタイプ** | 町グリッド＋建物3種＋村人3人が家↔職場を歩く最小シーン。カメラ方式の確定 | `TownViewport` 試作ブランチ | 眺めて「生活に見える」か自分で判定。ここで駄目なら柱1を再設計 |
| **1. 町の器** | 全施設の建物化、昼夜・天気、村人の配置と移動（仕事は現行ロジックのまま行き先だけ空間化） | 主画面が町3Dに置換 | 既存テスト緑（UI除く）、60fps、1日が問題なく回る |
| **2. 生活AI** | スケジュール＋欲求＋Utility AI、家・食事・就寝、今日のあしあと、任命／条例UI | 生活システム一式 | シミュレータで30日、飢餓・全滅が常態化しない。村人が夜に寝て朝起きる |
| **3. 経済v2** | 4.3の v2a→v2b→v2c を順に。家計簿、店価格、需要ボード、交易の可視化 | 経済一式 | シミュレータ30日で金庫・村人貯蓄・食料が破綻しない。価格が需給で動く |
| **4. ダンジョンv2** | ノードマップ化（まず森のみ→全5件）、パーティ、荷物、帰還判断、脅威の町接続 | ダンジョン一式 | 森で「行って帰る」が成立。全ダンジョンでボス到達可能（シム確認） |
| **5. 統合・仕上げ** | チュートリアル、周回SP再計算、管理モード、旧セーブ換算、公開（gh-pages） | v2 リリース | 全ゲート緑、README／設計docs を v2 に更新 |

進め方は従来どおり: 専用ブランチ（例 `feat/v2-polygon-town`）でフェーズごとにゲートを通して積み、master への統合はユーザーが行う。

**やらないこと（今回のスコープ外）**: マルチプレイ、村人の結婚・世代交代、装備強化+値、自由カメラ＋一人称、スマホ専用UIの作り込み（レスポンシブ追随まで）。

## 9. 決めてほしいこと（3点だけ）

**A. カメラ**: ①見下ろし＋90度回転＋ズーム（推奨・開発が速く生活が読める） ②完全自由カメラ ③2.5D固定（奥行きなし・一番軽い）
**B. 一新の進め方**: ①同一リポジトリでブランチ一新（推奨・資産とテストを活かす） ②別リポジトリで新規に作る ③現行版を残して v2 を並行公開
**C. 脅威度の決着**: ①現行どおり100%で即ゲームオーバー ②襲撃イベント＋防衛戦に緩和（推奨・町が見える新版と相性が良い）

この3点が決まれば、Phase 0 のプロトタイプ仕様（町のマス配置と建物リスト）まで落として着手できる。
